# MK Universe

**YOUR DIGITAL UNIVERSE** — منصة عربية تجمع السينما وصناع المحتوى والمجتمع والدردشة تحت هوية MK ID.

## مكونات التطبيق
- واجهة عربية RTL مصممة للهاتف، بألوان الأسود والفحمي والأحمر الداكن والبرتقالي والذهبي.
- الرئيسية وMK Cinema وMK Creators وMK Social وMK Chat وMK ID ولوحة المالك.
- تسجيل حساب وتسجيل دخول بالبريد الإلكتروني وكلمة المرور.
- ملفات شخصية، منشورات، تفاعلات، تعليقات، رفع وسائط، متابعة أعضاء، محادثات خاصة ومجموعات.
- إشعارات، بلاغات، أدوات إشراف وإدارة للمالك.
- دليل اكتشاف للأفلام والمسلسلات والأنمي وقنوات YouTube. الدليل لا يعني امتلاك حقوق بث هذه الأعمال.

## مصادر المحتوى والحقوق
- روابط المشاهدة يجب أن تكون HTTPS ومن مصادر رسمية أو مرخّصة، مع تسجيل أساس الحقوق قبل نشر عنوان في مكتبة السينما.
- فيديوهات YouTube تبقى مستضافة على YouTube عند تضمينها.
- لا تضف روابط قرصنة أو تعِد بث محتوى مدفوع من دون ترخيص.
- قائمة حفظ فيديوهات صناع المحتوى محلية على الجهاز/المتصفح وليست مزامنة بين الأجهزة.

## الأمان
- صلاحية المالك تتحقق من قاعدة البيانات والخادم؛ إخفاء عناصر لوحة الإدارة في الواجهة ليس بديلاً عن RLS والتحقق الخلفي.
- لا تضع مفاتيح Supabase السرية أو service_role في ملفات المتصفح أو GitHub.
- عمليات إدارة Auth الحساسة تمر عبر Edge Function مخصصة وتتحقق من صلاحية المالك.
- راجع سياسات RLS وStorage وEdge Functions قبل أي تغيير في قاعدة البيانات.

## التقنية
- Frontend: HTML/CSS/JavaScript ES Modules.
- Backend: Supabase Auth وPostgreSQL وRLS وStorage وRealtime وEdge Functions.
- فحص الكود: `npm run check`.

## الفروع والنشر
- `main`: النسخة الأساسية؛ لا تُعدّل أو تدمج إليها دون موافقة صريحة من صاحب المشروع.
- `mk-universe-v2`: فرع العمل الحالي، وهو الفرع المتصل بخدمة Render.
- `mk-universe-rebuild`: فرع أقدم مرتبط بطلب السحب رقم 1؛ طلب السحب ما زال Draft ومفتوحاً ولم يُدمج.
- Render: `https://mk-universe.onrender.com`، والنشر التلقائي مفعّل عند وصول commit جديد إلى `mk-universe-v2`.
- GitHub Pages ليس مسار النشر الأساسي. تم جعل سير Pages يدوياً فقط لتجنب محاولات نشر تلقائية غير لازمة؛ لا تعتبر Pages منشوراً أو جاهزاً دون تشغيله واختباره بشكل مستقل.

## الحالة والاختبارات
- فحص JavaScript واختبارات smoke checks تتحقق من عناصر أساسية في الواجهة وتدفق المصادقة وحالات الفراغ.
- نجاح الفحوص الثابتة لا يثبت وحده أن Supabase أو جميع وظائف المتصفح اختُبرت end-to-end.
- يلزم اختبار التسجيل والدخول والخروج والملفات الشخصية والمنشورات ورفع الصور والفيديو والدردشة والبلاغات وأدوات الإدارة في متصفح حقيقي.
- يلزم اختبار رفض العمليات الإدارية عند استخدام حساب عضو عادي.
- تفعيل لوحة المالك يتطلب وجود حساب Auth بالبريد المصرح به وتأكيده؛ لا تشارك كلمة المرور أو أي مفاتيح سرية.
- يلزم إضافة سياسة خصوصية وشروط استخدام وآلية واضحة للإبلاغ والتعامل مع المحتوى المخالف قبل الإطلاق العام.
- لا يوجد APK مؤكد في هذا المستودع حالياً؛ تجهيز Android يأتي بعد استقرار نسخة الويب واختبارها على أجهزة فعلية.

## ملاحظات مهمة
- لا تشغّل ملفات SQL قديمة أو جزئية فوق قاعدة البيانات الحالية دون مراجعة مخطط Supabase وسياسات RLS الحالية أولاً.
- لا تحذف ميزات أو بيانات موجودة أثناء الإصلاح.
- لا تدمج إلى `main` ولا تغيّر إعدادات البنية التحتية دون موافقة صريحة.
