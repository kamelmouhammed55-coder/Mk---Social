# MK Universe

**YOUR DIGITAL UNIVERSE** — تطبيق واحد يجمع السينما والمجتمع والدردشة تحت هوية MK ID.

## الموجود في فرع التطوير
- واجهة عربية RTL متجاوبة بتصميم أسود/فحمي مع الأحمر والبرتقالي والذهبي.
- أقسام الرئيسية وMK Cinema وMK Creators وMK Social وMK Chat وMK ID ولوحة المالك.
- تسجيل الدخول بالبريد الإلكتروني وكلمة المرور، وإنشاء حساب جديد.
- ملفات شخصية ومنشورات وتفاعلات وتعليقات ورفع وسائط ومحادثات خاصة ومجموعات.
- دليل استكشاف مختار للأفلام والمسلسلات والأنمي وقنوات يوتيوب؛ ليس مكتبة شاملة أو ترخيصاً لإعادة نشر المحتوى.
- روابط المشاهدة يجب أن تكون رسمية أو مرخصة. فيديوهات YouTube تبقى مستضافة على YouTube عند تضمينها.

## المالك والأمان
- بريد المالك المصرح به محفوظ في قائمة السماح داخل قاعدة البيانات.
- يجب إنشاء حساب بالبريد المصرح به وتأكيد البريد حتى تتفعّل صلاحيات المالك.
- لا تضع مفاتيح Supabase السرية أو service_role في ملفات المتصفح أو GitHub.
- عمليات الإدارة الحساسة يجب أن تتحقق من صلاحية المالك في الخادم، وليس من بيانات يرسلها المتصفح فقط.

## التقنية
- Frontend: HTML/CSS/JavaScript ES Modules.
- Backend: Supabase Auth, PostgreSQL, RLS, Storage, Realtime وEdge Functions.
- فحص الكود: `npm run check`.

## الحالة الحالية
- `main`: النسخة السابقة.
- `mk-universe-rebuild`: فرع التطوير الحالي.
- Pull Request #1 ما زال Draft ومفتوحاً، ولم يتم دمجه.
- اختبار التحقق الأخير نجح.
- آخر محاولة نشر GitHub Pages فشلت؛ لذلك لا تعتبر رابط Pages منشوراً أو جاهزاً حتى ينجح Deploy workflow ويتم فتح الموقع واختباره.

## المطلوب قبل الإطلاق العام
1. التأكد من تفعيل GitHub Pages واختيار **GitHub Actions** كمصدر للنشر.
2. إعادة تشغيل Deploy workflow وتشخيص أي فشل جديد من سجل المهمة.
3. مراجعة إعدادات Supabase Auth وRedirect URLs وسياسة تأكيد البريد بما يتوافق مع تدفق Email + Password.
4. إنشاء حساب المالك بالبريد المصرح به وتأكيده، ثم التأكد من ظهور لوحة المالك.
5. اختبار التسجيل والدخول والخروج والملفات الشخصية والمنشورات ورفع الصور والفيديو والدردشة والبلاغات وأدوات الإدارة في متصفح حقيقي.
6. اختبار رفض العمليات الإدارية عند استخدام حساب عضو عادي.
7. مراجعة سياسات RLS وStorage وEdge Functions وعدم كشف مفاتيح الخادم.
8. إضافة سياسة الخصوصية وشروط الاستخدام وآلية الإبلاغ والتعامل مع المحتوى المخالف.
9. إضافة محتوى سينمائي فقط بروابط رسمية أو تراخيص واضحة، ومراجعة حدود التخزين والتكلفة.
10. بعد اجتياز الاختبارات وموافقة صاحب المشروع، مراجعة PR ثم دمجه إلى `main` ونشر النسخة العامة.
11. بعد استقرار نسخة الويب، تجهيز PWA أو Android APK واختباره على أجهزة فعلية؛ لا يوجد APK جاهز حالياً.

نجاح فحص الصياغة والاختبارات الثابتة لا يعني أن جميع وظائف التطبيق اختُبرت في المتصفح أو أن النشر نجح.
